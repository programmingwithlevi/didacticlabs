# Amazon Simple Storage Service (S3)

> **Core Concept:** Object storage built to store and retrieve any amount of data from anywhere—flat namespace, key-value storage, and high durability.

---

## 1. Whitepaper & Theoretical Foundation

Amazon Simple Storage Service (S3) is an **object store**, not a block store (like EBS) or a file system (like EFS). Instead of directories and file hierarchies, S3 stores files as **objects** inside **buckets**.

### Key Architectural Concepts

* **Buckets:** Top-level containers for objects. Bucket names reside in a global namespace and must be globally unique across all AWS accounts.
* **Objects:** The fundamental entities stored in S3. An object consists of:
  * **Key:** The unique name/path identifying the object within the bucket (e.g., `images/logo.png`).
  * **Value:** The raw binary data (payload).
  * **Version ID:** Unique identifier when bucket versioning is enabled.
  * **Metadata:** Arbitrary name-value pairs describing the object (e.g., `Content-Type: image/png`).
* **Consistency Model:** S3 provides **strong read-after-write consistency** for `PUT` and `DELETE` requests of objects in all AWS regions.

### Storage Classes & Lifecycle Rules

S3 offers different storage tiers optimized for access patterns and cost:

1. **S3 Standard:** Frequent access, low latency, high throughput.
2. **S3 Standard-Infrequent Access (S3 Standard-IA):** Lower storage cost, but incurs retrieval fees; designed for data accessed less frequently.
3. **S3 Glacier Flexible / Deep Archive:** Low-cost storage for long-term archival with retrieval times ranging from minutes to hours.
